# Vacationist SEO & GEO Strategy

Living reference for search and AI-answer-engine visibility. Covers all 9 SEO pillars for `vacationist.app`. Items marked **✅ Implemented** are live in the repo as of 2026-08-05 (see `marketing/site/build.mjs` and `docs/`); items marked **📋 Planned** are recommendations for a future pass.

**Non-negotiable constraint:** `docs/**` is generated output. All site changes land in `marketing/site/content/**`, `marketing/site/build.mjs`, `marketing/site/og-image.mjs`, `marketing/site/site.css`, `docs/index.html` (hand-authored homepage), or `docs/i18n/{en,de}.js`. Never hand-edit generated HTML — a rebuild will silently overwrite it. Verify every change with `npm run build:site` run twice; the second run must produce a zero `git diff`, **including binary output** (`docs/assets/og/*.png`) — hash the full `docs/` tree, not just `.html`/`.xml`/`.css`, since PNG encoding is a real place non-determinism can sneak in (see Pillar 8).

## 1. Technical & Core Web Vitals SEO

**✅ Implemented / already strong:**
- Homepage CSS is fully inlined in `docs/index.html` — zero render-blocking external stylesheet request for the highest-traffic page.
- Generated pages load one external stylesheet (`docs/assets/site.css`) plus a self-hosted, latin-subset variable font (`InterVariable-latin.woff2`) via `<link rel="preload">` + `font-display: swap` — no third-party font requests, no FOIT.
- `robots.txt` (`docs/robots.txt`) explicitly allows the major AI/answer-engine crawlers (GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-Web, PerplexityBot, Google-Extended, Applebot-Extended, CCBot) in addition to the default `Allow: /` — a positive signal that survives future default-deny changes by any one of them.
- `docs/sitemap.xml` is fully generated by `build.mjs` (`renderSitemap()`), deterministic, includes `xhtml:link` hreflang alternates per cluster, and correctly excludes `noindex` pages (`/impressum.html`, `/join.html`, `/404.html`).
- Canonical URLs are set on every page via `renderPage()`'s `<link rel="canonical">`, always pointing at the trailing-slash directory URL — no parameter or session-ID variants exist to canonicalize away.
- **RSS 2.0 feeds** for the blog (`docs/blog/feed.xml`, `docs/de/blog/feed.xml`), generated by `renderRssFeed()` in `build.mjs` from the same post front matter the blog indexes use. `<link rel="alternate" type="application/rss+xml">` autodiscovery is on every page (both languages), not just the blog index — feed readers, aggregators, and some crawlers use this as a lightweight freshness signal independent of `sitemap.xml`'s `lastmod`. `lastBuildDate` is derived from the newest post's front-matter date, never `Date.now()`, preserving build determinism.

**📋 Planned:**
- **Lighthouse/PageSpeed baseline.** No CI-integrated Lighthouse run exists today. Add a manual quarterly check (`npx unlighthouse --site https://vacationist.app`) — automating this into `npm run build:site` is out of scope until traffic justifies the CI cost.
- **`Sitemap:` ping automation.** Currently manual ("resubmit sitemap.xml in Search Console" — see Release Strategy checklist). Not worth automating for a static-hosted 58-page site.

**Canonical rules for web-app subroutes vs. marketing pages:** The marketing site (`vacationist.app`, this repo's `docs/`) and the web app (`web.vacationist.app`, a separate Expo web export) are different origins with no shared canonical cluster — this is correct and intentional. The web app is an authenticated product surface (trip screens, `/join?token=`) that should never compete for the same query intent as the marketing pages, so it carries no SEO metadata of its own and is excluded from `docs/sitemap.xml`. Do not add cross-origin canonical tags between them.

## 3. AI SEO / Generative Engine Optimization (GEO)

- **`docs/llms.txt`** — a structured Markdown entity summary purpose-built for LLM ingestion: what Vacationist is, core features, a dedicated **Comparisons** section framing Vacationist against Splitwise/Wanderlog/TripIt/Tricount/Troupe in two sentences each (the exact "authoritative comparison text" GEO strategies call for), full bilingual URL index, pricing, and company info. Every URL in the file must be a Markdown hyperlink (`[text](url)`), never bare text — Lighthouse's Agentic Browsing audit (default since Lighthouse 13.3.0, May 2026) flags the file as "contains no links" otherwise. Kept hand-maintained (not build output) and updated whenever new pages ship. `apps/mobile/public/llms.txt` covers the separate web.vacationist.app origin with a short pointer back here.

## 6. International & Multilingual SEO (Hreflang)

**✅ Implemented — validated at build time, not just written and hoped correct:**
- `hreflang="en"` / `de` / `x-default` triads on every clustered page, generated by `hreflangLinks()` from front matter `altPath:`.
- **Build-time bidirectionality check** (`build.mjs`, `main()`): throws a build error if any page's `altPath` doesn't point back at a page whose own `altPath` points to the original — this class of hreflang bug (one-directional pointing, the most common hreflang mistake sites make) is structurally impossible to ship here.
- URL strategy: **subfolder `/de/`**, not query parameters — the correct choice for crawlability (query-param locale switches are frequently not crawled/indexed as distinct pages). `/` = English (default, `x-default`), `/de/` = static German homepage generated from `docs/index.html` + `docs/i18n/de.js`.
- DE-first language switcher ordering (`DE` before `EN`) sitewide, reflecting DACH as the primary non-English audience — implemented in `navHtml()`.
- Localized metadata (title, description, OG/Twitter, keywords) fully translated per page, not just the visible body copy.

**📋 Planned:**
- **`/de/scan/android-qr/` does not exist** — the QR-landing page (`docs/scan/android-qr/index.html`) is bilingual via client-side `i18n.js` toggle (`window.I18N_DEFAULT_LANG = 'de'`) rather than a static German URL. This is intentional (it's a print/QR destination, not an organic-search target), but note it as the one page outside the hreflang system by design, not oversight.
- Consider a static `/de/` counterpart for `/scan/android-qr/` only if it starts picking up organic (non-QR-scan) traffic in Search Console — unlikely for a print-QR destination, so low priority.

## 9. App Store Optimization (ASO) & Deep Linking

**✅ Implemented — Android App Links, real and verified:**
- `docs/.well-known/assetlinks.json` is live at `https://vacationist.app/.well-known/assetlinks.json`, scoped to `com.vacationist.mobile` with the correct SHA-256 cert fingerprint, `delegate_permission: common.handle_all_urls` — this is what lets Android treat `https://vacationist.app/join?token=...` links as native app opens instead of browser opens.
- `apps/mobile/app.config.ts` Android `intentFilters`: `autoVerify: true`, scoped to `pathPrefix: /join`, `category: [BROWSABLE, DEFAULT]` — matches the assetlinks.json scope exactly.
- `docs/join.html` implements the practical fallback pattern: attempt `vacationist://join?token=...` custom-scheme open, `visibilitychange` + 2.5s timeout to detect success, fall back to `web.vacationist.app/join?token=...` if the native app didn't open. This covers the case App Links alone don't (a user without the app installed).

**✅ Implemented — iOS Universal Links, shipped 2026-08-10.** iOS went GA on the App Store (`https://apps.apple.com/us/app/vacationist/id6800049398`, App Store Connect id `6800049398`, Team ID `93VX3MQ439`) as of v1.30.0:
- `apps/mobile/app.config.ts`'s `ios` block has `associatedDomains: ['applinks:vacationist.app']`, mirroring the Android `intentFilters` pattern.
- `docs/.well-known/apple-app-site-association` is live, served as `application/json` via a dedicated Cloudflare Transform Rule (`aasa_content_type`, ruleset `4722ba5424cc4b409525deabe507800a`) — GitHub Pages serves extensionless files as `application/octet-stream` by default, which Apple's AASA fetcher rejects, hence the rule:
  ```json
  {
    "applinks": {
      "apps": [],
      "details": [
        {
          "appID": "93VX3MQ439.com.vacationist.mobile",
          "paths": ["/join*"]
        }
      ]
    }
  }
  ```
- `docs/join.html`'s existing `vacationist://` custom-scheme + `visibilitychange`/timeout fallback pattern already worked cross-platform, so no separate iOS branch was needed there — the AASA file just adds the "tap a link, app opens directly" case on top of it.
