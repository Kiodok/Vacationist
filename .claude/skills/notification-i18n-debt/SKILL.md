# Push notification i18n debt

Push notification bodies are generated by PostgreSQL trigger functions which produce English-only strings (e.g., `"Marco added "Beach Volleyball" to "Paris Trip"."`). The Edge Function (`supabase/functions/push-notification/index.ts`) prefers the DB body over the generic translated body, so German-locale users receive contextual English text in push notifications instead of a generic German sentence.

**Why:** Accepted V1 trade-off — contextual detail (who did what, in which trip) is more useful than generic locale-correct text. Identified during the June 2026 notification enhancement work (see [[batch-june2026-fixes]]).

**How to apply:** When i18n is implemented more broadly, the trigger functions will need to either (a) produce locale-neutral data and let the Edge Function compose the message in the user's language, or (b) have the Edge Function query the target user's locale and compose the body string from structured data rather than using the pre-formatted DB body. The `NOTIFICATION_TRANSLATIONS` map in the Edge Function is the right place to centralize this — extend it with parameterised templates once the approach is decided. Don't "fix" this unilaterally by dropping the DB body — confirm the trade-off is being revisited before changing this behavior.
