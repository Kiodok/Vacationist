# Offline UX conventions

The offline overhaul (2026-06-12) established conventions that every NEW mutation/screen must follow:

1. **Buttons/sheets**: close sheets BEFORE `mutate()` (never in `onSuccess`); pass `isPending={isMutationBusy(mutation)}` (`apps/mobile/src/utils/mutationStatus.ts`) — a paused (offline-queued) mutation keeps `isPending: true` forever, so raw `isPending` freezes buttons offline. Exceptions that keep `onSuccess`-close: `NudgeSheet`, document access request (`settings.tsx`), `CopyPackingListSheet`.
2. **Loading states**: use `getQueryDisplayState(query)` from `apps/mobile/src/hooks/useOfflineAwareQuery.ts` → `showSkeleton` / `showOfflineEmpty` (render `OfflineEmptyState`) / `refreshing` (RefreshControl). Never use `isFetching` for spinners — paused fetches keep it true forever.
3. **New mutations**: add a self-contained `*Variables` type in `packages/types` (tripId in variables, not closure), `mutationKey`, `onMutate` optimistic + `onError` rollback in the hook, mutationFn + `onSuccess` (invalidation + toast) in `apps/mobile/src/utils/mutationDefaults.ts`, and the key in `PERSISTED_MUTATION_KEYS` (`queryClient.ts`). ~50 mutations are now persisted (activities, notes, packing/stuff, accommodations, transfers, updateTrip, expenses, shopping, votes, notifications). `persistedMutationKeys.test.ts` fails the build if a key has no matching `setMutationDefaults` (or vice-versa).
4. **Deliberately NOT persisted**: travel documents, profile/invites/members, sendNudge, copyPackingList, prework, recipes, transfer passenger assignment (stale set-replace risk). Since v1.39.0 the mutation-cache subscriber (`queryClient.ts`) **drops a paused non-persisted mutation from the cache** after its "could not be saved" toast — left paused it would fire on reconnect and duplicate a manual retry (two trips, two invites). That is what makes `isMutationBusy` safe on these buttons.
5. **Optimistic rows must survive a restart (v1.39.0).** The queue survives a kill; the optimistic rows it produced do not (`stripOptimisticRows` removes them, and `onMutate` lives in a hook that doesn't exist at boot). Put the cache patch in a pure helper (`features/<feature>/utils/*Cache.ts`), shared by the hook's `onMutate` and by `REHYDRATORS` in `utils/optimisticRehydrate.ts` (idempotent; only patches an already-loaded cache; test-enforced to be persisted keys only). If an item is readable through TWO query keys, the helper writes both — shopping: `['shopping-lists', id, 'items']` + `['trips', id, 'all-shopping-items']` (writing one was the "added offline, missing from All Items" bug). Registered today: create/update/updateGlobal/delete shopping item, `createExpense`.
6. **The bottom offline bar is gone (v1.39.0).** `OfflineNotices` (launch toast once + "All changes synced" after a drained reconnect) and `OfflineIndicator` (header chip on the Trips tab + trip screen) replaced `OfflineBanner`; there is no change counter anywhere. The Supabase client has a 15s fetch timeout (60s for `/storage/v1/`). Default `staleTime` is 30s.
7. **Persistence lifetimes (Phase 19)**: query cache = `maxAge: 30d` + `buster` (app version) in `QueryProvider.tsx` — no more hand-bumping `REACT_QUERY_CACHE_v2`. The offline mutation queue is persisted **separately** in MMKV `MUTATION_QUEUE_v1` (`utils/mutationQueue.ts`), so it survives a query-cache eviction. Auth boot: see [[offline-session-durability]].

**Why:** `offlineFirst` networkMode pauses mutations/queries offline; UI treating "paused" as "in-flight" caused stuck buttons and infinite spinners.

**How to apply:** when adding any feature mutation or list screen, copy the pattern from `useActivities.ts` / `activities.tsx` (for a create that adds a visible row, also `useShoppingItems.ts` + `shoppingItemCache.ts`); never reintroduce raw `isPending` props or `isFetching`-driven spinners directly.
