# GEO structure + citations pass — 2026-09-24

Follow-on to [[seo-aeo-pass-2026-09]]. Staged (not committed) pass adding answer-passage structure and a citation layer to vacationist.app. Full record: `marketing/seo-strategy.md` § Pillar 3 and the "Shipped 2026-09-24" summary entry. Plan: `C:\Users\Gary\.claude\plans\calm-questing-seal.md`.

**Same-day correction (Tech Lead): hosting is Switzerland (Zurich, `eu-central-2` — Supabase labels it "Central Europe (Zurich)"), not the EU (Paris).** This pass initially inherited the wrong "EU, not Switzerland" hosting claim from [[seo-aeo-pass-2026-09]] and built the citation register, `#facts` section, and several FAQ/content answers around it. All of it was corrected in the same session once the Tech Lead caught it — every "Paris"/"eu-west-3" instance across the site was swept (see the correction note at the top of `marketing/geo-citations.md`). **The rest of this skill file describes the finished, corrected state** (post-fix) unless a line says otherwise.

## The evidence that set this pass's priorities (verified via web research 2026-09-24)

- **Structure is the best-evidenced lever, not citations or llms.txt.** A March 2026 controlled study that varied *only* structural formatting (headings, chunking, visual emphasis) while holding content constant measured a **+17.3% citation-rate lift across six generative engines**. The homepage had 1×h1/7×h2/**zero h3** across 1,603 lines before this pass — real content (FAQ questions, feature titles, use-case titles) was in `<div>`/`<span>`, not headings.
- **`llms.txt`-shaped files are a hedge, not a lever — don't over-invest.** Across ~500M AI-bot visits, only ~0.1% of requests ever targeted `llms.txt`; no major AI vendor (OpenAI/Google/Anthropic) commits to reading the format. `llms-full.txt` and per-page `.md` twins were still built (cheap, Tech-Lead-approved), but never treat them as the priority.
- **Ceiling for calibration:** 84–85% of AI brand citations come from third-party pages, not the brand's own domain. This pass makes Vacationist *citable and accurate when reached* — it can't make engines reach it more often. Off-page work (third-party listings, Reddit, Product Hunt) is a separate, unaddressed lever — see [[marketing-growth-plan-q4-2026]].

## What shipped

- **Three new homepage sections**, purely additive between `#compare` and the trust strip: `#glossary` ("In plain terms," 6 terms — group blocker, settle-up plan, guest join, business cost flag, per-item currency, organizer document access — each `<h3 id="term-*">`), `#fit` ("Honest fit" — explicit "use Vacationist when… / use something else when…," every "use something else" bullet already-approved copy from `/vs/*`, zero new comparison claims), `#facts` ("Checkable facts" — 4 rows, see citations below). FAQ expanded 7 → 12. Each `.faq-q` button is now wrapped in `<h3>`. Homepage heading count: 1×h1, 10×h2, 24×h3.
- **`marketing/geo-citations.md`** — new, unpublished, Tech-Lead-facing fact register. Rules: primary sources only, one-click verifiable, approved before copy ships, re-verified quarterly. Four sources landed this pass: **NIST FIPS 197** (AES-256), **GDPR Art. 32** (encryption named as an *appropriate* security measure — careful, it doesn't mandate encryption), **GDPR Art. 17** (right to erasure, backs the existing account-deletion flow), **Supabase's region docs** (confirms Switzerland/Zurich hosting — corrected same-day from an initial wrong "EU/Paris" claim, see the note above). Applied to the homepage `#facts` + `/features/travel-documents/` + `/blog/travel-document-safety-guide/` (EN+DE) — deliberately not spread to pages that make no sourceable claim.
- **New front-matter key `citations:`** (`Title::URL` pairs, `|`-separated — `::` not `:` because `parseFrontMatter()` splits on the first colon) → `Article.citation` / `WebPage.citation` (`CreativeWork[]`) in `jsonLd()`. Homepage's `homePageLd().citation` is fed by the same `fact.N.src`/`fact.N.src.href` i18n keys the visible `#facts` rows render — one source of truth for the link, the schema, and the register.
- **`DefinedTermSet`/`DefinedTerm` JSON-LD** (`definedTermsLd()`, `GLOSSARY_SLUGS`) mirroring `#glossary` exactly. While in there, fixed `howToLd()`'s hardcoded `[1, 2, 3].map(...)` to derive from `numberedKeys()` — same "Nth item silently missing from schema" bug class `faqNumbers()` was introduced to prevent for FAQ, now closed for HowTo too.
- **`llms-full.txt`** (EN-only, ~220KB; legal pages summarized not inlined) **+ per-page `.md` twins** for every generated page (`docs/<path>/index.md`, `<link rel="alternate" type="text/markdown">`). Both fed by one shared `cleanPageBody()` renderer so they can't diverge. Homepage twins (`docs/index.md`/`docs/de/index.md`) are **generated** from the i18n dictionaries via `homeMarkdown()` — never hand-maintained.
  - **`homeMarkdown()` throws if a new numbered `feat./use./how./faq./gloss./fit./fact.` key exists in `en.js`/`de.js` but is never rendered.** This is the guard: adding a homepage section must extend `homeMarkdown()` in the same change, or the build fails. Don't remove this check when adding a new section — extend the function instead.
- **Eliminated the EN `FAQPage`'s hand-sync burden.** `homeFaqLd(lang)` is now used for both `syncEnglishHomepageAppLd()` and `renderGermanHome()` (DE already auto-derived; EN was hand-authored JSON-LD in `docs/index.html` before this pass). All 7 homepage LD blocks (`SoftwareApplication`, `WebSite`, `WebPage`, `Organization`, `FAQPage`, `HowTo`, `DefinedTermSet`) are now build-managed via `replaceLdBlock` — zero hand-authored JSON-LD left on the page.
- **New `marketing/site/site.test.js`** (30 assertions, wired into `npm run test:site` — there was no JSON-LD/build test before this pass). Rebuilds the site first, then checks: every JSON-LD block parses; homepage carries exactly the 7 expected `@type`s on both languages; `FAQPage.mainEntity` count matches `faq.N.q` keys on both; every `DefinedTerm.url` fragment resolves to a real `id=`; every `speakable.cssSelector` matches a real class (not orphaned); `SoftwareApplication.softwareVersion` matches `apps/mobile/app.config.ts`; `aggregateRating` stays gated below 25 reviews; `en.js`/`de.js` load cleanly with identical key sets; **no English i18n value leaks into `docs/de/index.html`**; every `citation.url` is absolute `https://`.

## Bugs found and fixed along the way (not the original task — fixed per CLAUDE.md's "fix pre-existing issues" rule)

- **`.reveal { opacity:0 }` had no `<noscript>`/no-JS fallback** (`docs/index.html`) — every section, old and new, was invisible to any CSS-aware renderer that doesn't execute JS or never fires the `IntersectionObserver`. This quietly undercut the 2026-09-20 pass too. Fixed: an early `<script>document.documentElement.classList.add('js')</script>` + the reveal rule became `.js .reveal`. No-JS renders fully visible immediately; JS-enabled fade-in behavior is unchanged. The Tech Lead explicitly chose this fix over a `<noscript>`-only alternative.
- **Stale timezone copy.** `feat.6.desc` / `docs/llms.txt` still said activities were "displayed in the trip's timezone" — false since v1.39.0 removed all timezone display/selection (see [[floating_wall_clock_times]]). Also `docs/privacy-policy.html` + `docs/delete-account.html` (+ DE content-file equivalents) described `users.timezone` as "set during onboarding" — it's actually silently auto-detected, never user-facing. All fixed EN+DE.
- **Two "Is this feature free?" FAQ answers on `/features/travel-documents/` (EN+DE)** implied a paid tier exists ("check the current plan details… on every tier") — these two instances survived the 2026-09-20 "remove premature Pro copy" sweep. Fixed to present-tense free-only, per the standing rule in [[marketing-growth-plan-q4-2026]] (never pre-announce Pro).
- **Two "Swiss/EU hosting" conflations** in the travel-document safety blog post's GDPR FAQ answer (EN+DE) — "built and hosted with Swiss/EU privacy standards" blurred the (then-believed) distinction between developer and hosting location. Fixed twice: once to match [[seo-aeo-pass-2026-09]]'s original "EU, not Switzerland" framing, then again same-day once that framing itself was corrected — now both developer and hosting are stated as Switzerland, plainly.
- **`nav.features` in `docs/i18n/de.js`** was the untranslated English word "Features" — every other nav item was correctly German ("So funktioniert's", "Anwendungsfälle", etc.). Caught by the new German-leakage test written for this pass — a live demonstration of why that test exists.
